# Overwatch AIO Skill & MCP 검증 기록

## 0.3.0 병행 제공 — 2026-09-09 KST

- Windows, Python 3.13 스킬 단독 환경: **293개 통과**. MCP SDK가 실제로 없음을 별도 프로세스에서 확인했다. MCP 전용 테스트 모듈 1개는 해당 환경에서 제외한다.
- Windows, Python 3.13 MCP 포함 환경: **333개 통과**. 스킬 단독 설치 전용 검사 2개는 별도 환경에서 수행한다. 같은 출처 fixture를 사용한 CLI/MCP 계약 검사는 72개다.
- Windows, Python 3.11.14: 빌드한 0.3.0 wheel을 별도 환경에 설치하고 개발 소스가 아닌 `site-packages`를 사용하는 상태에서 **293개 통과**. MCP 패키지 없이 스킬 실행·근거 관리·스키마 출력이 동작한다.
- 실제 stdio 실행 명령과 HTTP 서버에서 초기화, 10개 도구, 동일한 입력·출력 스키마, 오류 플래그, 원본 필터 보존, 정상 종료를 확인했다. HTTP 종료 검사는 테스트 프로세스의 표준입력을 닫아 Uvicorn의 정상 종료 절차를 요청한다.
- 한글·공백 경로와 다른 작업 폴더에서 DB 기본값·환경 변수·명시 경로의 우선순위를 검증했다. MCP 연결 중 별도 스킬 프로세스가 근거를 저장하고 MCP가 이를 읽는다. 기존 재생 검증과 사용하지 않는 `collection_jobs` 행은 보존되고 DB 무결성 검사를 통과했다.
- 입력 오류, 비공개 프로필, 429·503, 파싱 실패, 빈 결과, 오래된 캐시, 부분·전체 비교 실패, 잘못된 출력에 대해 두 방식이 같은 결과 본문을 반환한다. `status=error`만 MCP 오류다.
- Ruff 검사·포맷, Skill Creator 형식 검사, 스킬 메타데이터·참고 링크 검증을 통과했다. JSON/TOML 클라이언트 예제는 같은 실행 인수를 제공한다.
- source distribution에 스킬 루트·참고 문서·잠금 파일·MCP 예제가 포함된다. wheel에는 두 실행 명령·공통 코드·SQLite DDL이 포함된다. MCP는 선택 의존성이며 사용자 DB·가상환경·캐시를 배포하지 않는다.
- CI는 Windows/Linux × Python 3.11/3.13 × 스킬 단독/MCP 포함의 8개 조합으로 구성했다. 각 작업은 선택한 의존성 설치 여부를 확인하고 코드 검사·스킬 검증·전체 테스트·빌드를 실행한다. 원격 결과는 [GitHub Actions](https://github.com/BK927/overwatch-aio/actions/workflows/test.yml)에서 해당 커밋을 확인한다.

외부 출처 어댑터는 이번 변경에서 재작성하지 않았다. 아래 0.2.0의 실제 출처 조회 기록은 당시 관측이며, 이번 실행의 최신 출처 검증 결과로 취급하지 않는다.

## 0.2.0 전환 당시 기록

2026-09-09 KST, `overwatch-aio-skill` 0.2.0 전환 검증. 공개 출처의 응답은 시간에 따라 달라질 수 있다.

### 로컬 검증

- Windows, Python 3.13.14: 회귀 테스트 **291개 통과**. 기존 출처 파싱·필터·비율·캐시·근거 보존 테스트를 유지하고, 서버/수집 테스트를 제거했으며 출력 계약 검증을 CLI로 옮겼다.
- Windows, Python 3.11.15: 빌드한 wheel을 별도 환경에 설치하고 저장소 밖에서 동일 테스트 **291개 통과**. 설치된 `site-packages/overwatch_skill`을 사용하며 MCP·서버·수집 모듈이 없음을 확인했다.
- 실제 별도 프로세스의 CLI 검증 40개 포함. 설치된 실행 명령과 `python -m overwatch_skill`, UTF-8/BOM/한글 입력·출력, 다른 작업 폴더, 입력 파일 생략과 표준입력, 기본 DB 공유 및 DB 우선순위를 검증했다.
- 10개 조회와 주요 view의 응답 모델·JSON Schema·원본 확장 필드 보존을 검사했다. 503/429·파싱 실패·비공개 프로필·빈 결과·오래된 캐시·일부/전체 비교 실패·출력 계약 위반을 구분했다. 실행 실패는 `1`, 입력 오류는 `2`, 나머지 품질 상태는 `0`이다.
- 실제 프로세스에서 표준출력은 JSON 하나이고 진단은 표준오류로 분리됐다. 내부 디버그 정보나 traceback을 조회 결과에 노출하지 않았다.
- 이전 커밋 `5f50719`의 SQLite DDL로 만든 DB를 열어 저장된 명부·메타·캐시·리플레이 연결·재생 검증과 사용하지 않는 `collection_jobs` 행을 모두 보존하는지 검사했다. 새 DB에는 해당 수집 테이블이 없다.
- 근거 등록·신원 연결·실제 재생 확인 기록 명령이 별도 프로세스에서 저장한 결과를 다시 읽어 검증했다.
- MCP SDK가 없는 환경에서 조회·스키마 생성·패키지 빌드가 성공했다. `serve`, `collect`는 입력 오류이며 서버·수집 모듈/설정/배포 예제는 제거했다.
- Ruff 검사·포맷 검사, Skill Creator 형식 검사, 저장소에 포함한 스킬 메타데이터/참고 링크 검증을 통과했다.
- source distribution과 wheel에 개발 가상환경·캐시·사용자 DB·기존 모듈이 없음을 확인했다. 스킬 루트 파일은 source distribution에, SQLite DDL은 wheel에 포함된다.

### 실제 공개 출처 조회

MCP 없이 새 CLI의 조회 경계에서 14개 사례를 별도로 실행했다. 모든 사례는 정상 또는 예상된 빈 결과였고 종료 코드는 모두 0이었다. OverFast, Blizzard 원본 통계, OWTICS, OWReplays, Blizzard 패치, OWCS Korea를 확인했다. [실행 요약](live-verification.json)에 출처·시각·상태·건수·종료 코드를 기록했으며 공개 인물의 전체 응답이나 리플레이 내용은 저장하지 않았다. 검증 DB는 메모리에서만 사용했다.

공개 플레이어의 해당 영웅 통계가 없는 경우와 빈 한국 랭커 명부는 `EMPTY_RESULT`였다. 이를 0% 통계나 비공개 프로필로 바꾸지 않았다. 이 검사는 CI에서 자동 실행하지 않으며 `scripts/live_smoke.py`로 명시적으로 실행한다.

### 독립 스킬 동작 점검

별도 평가자가 스킬과 참고 문서를 읽고 오프라인 요청을 수행했다. 테스트 전용 DB와 다른 작업 폴더에서 상태·한국 랭커·아시아 마스터 라인하르트 이력·저장 리플레이를 조회했다. 자료가 없는 상태를 설명하고, ASIA를 한국 통계로 바꾸거나 근거 없이 리플레이를 재생 가능하다고 답하지 않았다. 확인된 개선점에 따라 오프라인 조회 안내를 추가하고 로컬 응답 출처 이름을 `cli`로 정리했다.

### CI와 확인 범위

GitHub Actions는 Windows/Linux × Python 3.11/3.13의 동일 회귀 검사, 스킬 형식 검사, 패키지 빌드로 구성되어 있다. 원격 실행 결과는 해당 커밋의 Actions에서 확인한다. 게임 클라이언트 실제 재생·실시간 관전은 이 스킬의 기능이나 검증 범위에 포함되지 않는다.
